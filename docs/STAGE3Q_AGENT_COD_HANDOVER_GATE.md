# Stage 3Q — local Agent COD recipient handover (draft)

Candidate stacked on draft PRs #38–#43. This is a schema-first gate and is not a production deploy authorization.

A selected, approved local Agent must first receive the Parcel from the destination hub through the verified handoff. The Agent may then send a one-use SMS delivery code to the Parcel recipient. At physical handover the Agent enters the code and the exact COD balance collected. The existing non-COD confirmation endpoint still rejects COD and the generic delivery-status endpoint remains blocked.

The new COD confirmation verifies active Agent context, assignment, latest Agent custody, contact phone binding, code expiry and attempts, Order eligibility and payment evidence, and the exact remaining balance. A wrong code increments attempts in a short committed transaction. Valid confirmation locks Order then Parcel and rechecks under the canonical seller release transaction. Custody event, immutable cash collection, Parcel/Order/Shipment status, tracking, informational Agent earnings and invoice receipt commit together. A wallet routing block or any failed write rolls back all of these. A retry cannot release or deliver twice.

Migration `1788280800000` adds nullable `order.codBalanceCollectedByLocalAgentId`, with a FK to the Agent profile and exclusivity against the existing Super Agent hub collector field. It also creates immutable `agent_cod_collection` rows uniquely tied to Order, Parcel and custody event. The cash liability is the full collected balance for marketplace COD, matching the hub trust model. Seller-arranged shipments have no Kentexa-held seller proceeds; only Kentexa's handling-fee share is recorded as owed to Kentexa. No historical collection is inferred. The table records the liability; an admin remittance/reconciliation action is a future gate and must append separate evidence rather than changing a collection row.

Gate: apply the prior custody migrations first, then this migration, then behavior. Prove rollback, concurrent retry, manual zero-fee treatment, wrong/expired code, amount mismatch, immutability and downgrade refusal on isolated PostgreSQL. Verify the Agent dashboard on a phone and buyer SMS delivery. Review cash custody policy and Agent remittance operations before enabling real COD Agent assignments at scale. The design does not add a parallel Shipment or payment engine.
