# Stage 3N — Order completion and Parcel custody boundary (draft)

Base: Stage 3M draft `9669f2e`, stacked on Stage 3L/3K. Production GitHub branch remains `5203db1`. This candidate is not a deploy approval.

Order buyer confirmation, public confirmation-token submission, and auto-confirm can release seller proceeds. The old `syncParcelDeliveredForOrder()` then independently wrote Parcel `DELIVERED` and Agent commission without examining physical custody. A buyer or payer is not necessarily the parcel recipient. The sync was best-effort after the financial transition; failure could leave Order and Parcel inconsistent.

This draft joins the custody check to the canonical `OrderReleaseService.releaseSellerProceeds()` transaction through `completeInTransaction` for buyer confirmation, online token confirmation, and auto-release. It locks Order (in OrderRelease) then Parcel and rejects an active hub or Agent custody event. A terminal recipient-contact event (`recipient_self_pickup` or `recipient_agent_delivery`) with terminal Parcel status is eligible. Recipient-selected delivery and hub-arrived Parcels without custody proof are blocked even if they lack an event. Historical Parcels in other statuses with no custody event keep their prior buyer-confirmation path; no history is invented.

Manual token confirmation, which has no Kentexa seller release, now locks Order then Parcel and applies the same guard before its Order update. The best-effort legacy Parcel projection locks Parcel and writes status/tracking together; it refuses to overwrite any Parcel with custody evidence or a pending recipient-selected delivery. This prevents a concurrent handover from being replaced by a late Order sync. Informational legacy Agent commission still happens after the projection and remains separate from the new verified Agent delivery writer.

This is intentionally a bounded gate. It does not convert Order confirmation into physical proof, nor does it retrofit all historical Parcels. Provider delivery, hub generic terminal status, and COD Agent cash-holder settlement remain separate. Before release, inspect legacy no-custody Orders and real partner flows, and prove real PostgreSQL blocked seller release, verified recipient completion, retry/concurrency, and projection behavior. CI runs the focused tests against an isolated database. A schema migration is not needed in this slice.
